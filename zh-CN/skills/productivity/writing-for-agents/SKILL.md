这是编写任何供 agent 使用的文档的参考——技能、`AGENTS.md` / `CLAUDE.md`，以及通过指针触达的文档。包装形式不同，写法却相同：同样的杠杆让每一种文档都可预测——让 agent 每次运行都走相同的*流程*，而不是产出相同的输出。

当你编写的文档是技能时，请阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式选择和路由技能。

## 上下文指针

**上下文指针（context pointer）**是保存在 agent 上下文中的一条引用，它指明某些上下文之外的材料，并编码了触达这些材料的条件。技能的 `description` 就是一个；`AGENTS.md` 中指名某文档的一行文字也是同一种东西。决定 agent 何时触达材料、以及触达得有多可靠的，是指针的*措辞*，而不是它的目标。一个必须有、却藏在措辞薄弱的指针后面的目标是一个不一致性 bug：先打磨措辞；只有在打磨无效时才把材料内联进来。

指针要做两件事——说明材料是什么，并列出应当触发触达它的**分支**（分支是文档所处理的一个独立情形，因此不同的运行会在其中走不同的路径）。常驻加载的指针，每个词在每一轮都要付出代价，所以它比正文更需要严格修剪：

- **把主导词前置**——指针正是它发挥触发作用的地方。
- **每个分支只保留一个触发词。** 给同一个分支改名的同义词，等于把一个分支写了两遍；合并它们，只保留真正不同的分支。
- **删除正文已经承载的身份信息。**

## 两种负载

你添加的每个文档和指针，都会消耗两种预算之一：

- **上下文负载（Context load）**——常驻加载的材料对 agent 窗口造成的成本：`AGENTS.md` 里的一行、技能的 `description`、任何每一轮都待在上下文中的东西，无论是否触发，都在消耗 token 和注意力。
- **认知负载（Cognitive load）**——落在人身上的成本：有哪些文档存在，以及何时该用哪一份。人就是索引。这不是需要最小化的成本——它是人类自主性的代价；在人的判断重要的地方花掉它，在不重要的地方移除它。

只通过指针触达的材料，以指针自身那一行为代价，免于上下文负载；完全没有指针的材料，则完全依赖认知负载。

## 信息层级

文档由两种内容类型构成——**步骤（steps）**（agent 执行的有序动作）和**参考资料（reference）**（按需查阅的定义、规则、事实）——二者可以自由混合：全为步骤（一份配方）、全为参考资料（评审规则、本技能），或两者兼有。核心决策是每一块内容在**信息层级（information hierarchy）**中所处的位置，这是一个按 agent 对材料需求的紧迫程度排序的阶梯：

1. **文件内步骤（In-file step）**——第一层级：agent 按顺序做什么。
2. **文件内参考资料（In-file reference）**——按需查阅。它常常是一组地位相当的平行内容（一次评审的所有规则同处一级）——这是一种合理的安排，不是坏味道。
3. **已披露参考资料（Disclosed reference）**——被推到单独的文件中，通过上下文指针触达，只有在指针触发时才加载。范围从同文件夹的相邻文件，一直到存放在任何地方、任何文档都可指向的完全外部参考资料。

往下推得太少，顶层就会臃肿；推得太多，又会把 agent 真正需要的材料藏起来。这组张力就是整个决策。

**渐进披露（Progressive disclosure）**是沿着层级向下移动——移出主文件、放到指针后面——从而让顶层保持清晰易读。它主要不是为了优化 token：这是保护层级的方式。分支是检验披露是否得当的最清晰标准：把每个分支都需要的材料内联，把只有部分分支会触达的材料推到指针后面。当文档包含步骤时，本该披露出去的文件内参考资料会把步骤淹没，使 agent 是否留意它们变成掷硬币——这是一个制造不一致的杠杆，而不只是影响可读性的杠杆。

**就近放置（Co-location）**是文件内部的配套手段：层级决定一块内容*要放到多靠下*，就近放置则决定它到了那里之后*旁边放什么*。把一个概念的定义、规则和注意事项放在同一标题下，而不是分散各处，这样读一部分时就能顺带读到它的邻近内容。检验标准：文档读起来应当像专门为 agent 编写的说明文档——分组整理的材料读起来就是这样；散落的材料则不然。（与重复不同：重复是把同一个含义写在两处；散落则是把同一个含义拆碎到很多地方。）

**蔓延（Sprawl）**是这里要提防的失败模式：文档就是太长了，哪怕每一行都有效且独特。注意力会被多余内容摊薄，每多一行，就多一行需要保持相关性的内容。解药就是那个层级阶梯：把参考资料披露到指针后面，并按分支或顺序拆分，让每条路径只携带它所需的内容。

## 步骤与完成标准

每个步骤都以一条**完成标准（completion criterion）**收尾——即告诉 agent 工作已完成的那个条件。有两个特性使它成为有效杠杆：

- **清晰度（Clarity）**——agent 能否区分已完成和未完成？含糊的界限（“达成理解”）会招致**过早完成（premature completion）**：在步骤真正完成之前就结束它，注意力滑向了*完成本身*。仍在前方可见的步骤——**完成后步骤（post-completion steps）**——提供拉力；标准的清晰度则是阻力。按以下顺序防御：**先打磨界限**（局部且成本低）；只有在界限确实无法消除模糊、*并且*你观察到仓促行为时，才通过拆分顺序把后续步骤藏起来——而隐藏只有在跨越真实上下文边界时才有效（一次交接或一次子 agent 派发；内联调用会让后续步骤仍留在上下文中，什么也清不掉）。
- **要求（Demand）**——它要求做到什么程度。“每个修改过的模型都要交代清楚”能迫使工作做扎实，而“产出一份变更清单”则不能。要求驱动**跑腿工作（legwork）**——agent 在任务内部进行的挖掘，它潜藏在措辞中，而不是写成独立步骤——而且它不局限于步骤：“每条规则都已应用”约束着一组平行参考资料，正如“每个步骤都已完成”约束着一个顺序流程；正因如此，纯参考资料型文档也能带有穷尽性标准。

最强的标准既可核查，又具有穷尽性。

## 何时拆分

把一份文档拆成两份，会消耗两种负载之一，所以只有当这次拆分物有所值时才拆：

- **按顺序（By sequence）**——当完成后步骤会诱使 agent 草草处理眼前这个步骤时，拆开这段连续步骤。让后续步骤不在视野内，能促使 agent 在当前任务上做更多跑腿工作。也要警惕反方向：合并顺序会让每个步骤的后续步骤暴露给后面的内容，诱发过早完成。
- **按调用方式（By invocation）**——技能特有：参见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 主导词

**主导词（leading word）**是一个已经存在于模型预训练中的紧凑概念，agent 在运行文档时借助它思考（_lesson_、_fog of war_、_tracer bullets_）。它始终作为单个 token 重复，而不是作为一句话出现；它累积出分布式定义，并通过调动模型已有的先验，用最少的 token 锚定一整片行为。如果你能清晰定义，自造一个词也可以，但生造的词调动不了任何先验——预训练词汇免费给你的东西，你要用定义 token 去支付；所以先找现成的词。

它发挥两次锚定作用。在正文中是*执行*：每当这个词出现，agent 都会采取同样的行为；在平行参考资料中，它把注意力集中到一类要寻找的事物上。在指针中是*调用*：当同一个词出现在你的提示词、文档和代码库中时，agent 会把这套共同语言与材料联系起来，从而更可靠地触达材料。

主动寻找用主导词进行重构的机会。在三处分别展开的同一组三要素、用一整句话指向一个想法的指针——每一处都在恳求被折叠成一个 token：

- “快速、确定、低开销” → _tight_（一个 _tight_ 循环）。
- “一个你信得过的循环” → _red_——一个模糊的门槛变成了可观察的二值状态（循环在 bug 上变 _red_，或不变）。

你会赢两次：token 更少，同时给 agent 一个更锋利的思维挂靠点。假定每份文档都带着可以由主导词退役的重复表述——去把它们找出来。

**否定（Negation）**是这个杠杆旁边的失败模式：靠禁令来引导，会把被禁止的行为拖进上下文，让它变得*更*容易被唤起，而不是更不容易。_不要想大象_，结果满脑子都是大象；否定只是一个无力修饰词，会被强烈激活的概念冲垮，于是禁令读起来有一半像在做这件事的指令。要提示**肯定**的表述——陈述目标行为（“写单行注释”），这样被禁止的行为就永远不会被说出口。禁令只有在它是一条无法用肯定方式表述的硬护栏时才配占有一席之地；即便如此，也要把它与肯定目标配对，让注意力落在该做什么上。

## 修剪

- 把每个含义都放在**单一事实来源（single source of truth）**中：只有一个权威位置，这样改变行为只需在一处修改。**重复（Duplication）**——同一个含义出现在不止一个地方——会增加维护成本和 token 消耗，还会让一个含义在层级中的突出程度超过它的实际地位。（它是主导词的意外反面：主导词有意重复一个 token，而绝不重复含义。）
- **环境（environment）**也是事实来源之一——`package.json` 脚本、配置文件、目录布局、`--help` 输出——而重述这些内容的文档就是一个**缓存（cache）**：一次查找的副本，只有当查找代价高昂时，它才配得上所占的负载。要缓存 agent 靠看找不到的东西：不成文的约定、某个选择背后的原因、任何配置都不会坦白的坑。把单文件、单命令就能完成的查找留给环境，在那里它们不会过期。
- 检查每一行的**相关性（relevance）**：它是否仍然关系到文档所做的事？一行文字失去相关性，要么是因为它从来就与任务无关（纯粹的说明性文字，或者本应披露出去的分支），要么是因为它所描述的行为或世界已经改变而变得过时。较短的文档更容易保持相关性。没有修剪纪律，默认结局就是**沉积物（sediment）**：因为添加让人安心、删除显得冒险而沉淀下来的过时层，直到你必须一层层钻穿它们，才能找到仍然有效的内容。
- 逐句排查**空操作（no-ops）**：模型默认就会遵守的指令，付出负载却什么也没说。检验标准——与默认行为相比，它是否改变了行为？——是相对于模型而言的，不是相对于读者而言的：两个人对一个空操作有分歧，其实是对默认行为有分歧，解决方式是运行这份文档，而不是争论。当一句话不合格时，删掉整句话，而不是删减其中的几个词。这一检验也能给主导词打分：一个弱到无法胜过默认行为的词（当 agent 已经比较彻底时用 _be thorough_）就是空操作，解决办法是换一个更强的词（_relentless_），而不是换一种技巧。
