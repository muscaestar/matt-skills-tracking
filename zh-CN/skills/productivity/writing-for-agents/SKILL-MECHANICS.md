# 技能机制

这是 [`writing-for-agents`](SKILL.md) 中针对技能的部分：当文档是一个技能时，哪些地方会有所不同——frontmatter、调用方式的选择，以及路由技能。关于如何编写它的其他所有内容，都在 `SKILL.md` 这份通用参考中。

## 调用方式

有两种选择，它们在这两种负载之间做权衡：

- **模型调用（model-invoked）**的技能保留一个 `description`，这样 agent 可以自主触发它——其他技能也可以触达它。你仍然可以输入它的名字：模型调用始终*包含*用户触达；`description` 只会增加 agent 的发现能力，永远不会剥夺人的触达。`description` 是技能的顶层上下文指针，必须始终保持加载——用永久的上下文负载换取可发现性。内容全为参考资料的模型调用技能，也是共享参考资料的一个归属地：其他技能可以调用它，因此多个技能都需要的参考资料可以集中在一处。机制：省略 `disable-model-invocation`，写一个面向模型的 `description`，并包含触发分支（`SKILL.md` 中的指针编写规则完全适用）。
- **用户调用（user-invoked）**的技能让 `description` 脱离 agent 的触达范围：只有输入其名字的人可以调用它，其他任何技能都不行。上下文负载为零，但它消耗认知负载——你就是必须记住它存在的索引。机制：设置 `disable-model-invocation: true`；`description` 变成面向用户的——一行摘要，去掉触发词列表。

只有当 agent 必须自行触达该技能，或其他技能必须触达它时，才选择模型调用。如果它只会被手动触发，就把它设为用户调用，不付出任何上下文负载。

两个用户调用技能都需要的共享参考资料，不能放在其中任何一个里——没有 `description`，它们谁也无法调用对方。把它放到技能系统之外的普通文件中：任何技能都可以指向的外部参考资料。

## 按调用方式拆分

按调用方式的拆分（按顺序的拆分在 `SKILL.md` 中）：当你有一个明确的主导词，本身就应触发它——一个你在提示词中确实会使用的触发词——或者另一个技能必须触达它时，就拆出一个模型调用技能。你要为这个新的常驻加载的 `description` 付出上下文负载，所以这种独立触达必须物有所值。

## 路由技能

当用户调用技能多到记不住时，可以用一个**路由技能（router skill）**来化解堆积起来的认知负载：一个用户调用技能，列出其他技能的名字，以及何时该使用每一个；这样用户只需要记住一个技能，而不是很多个。它只能提示，永远不能触发它们：用户调用技能没有 `description`，所以除用户本人之外，谁也无法触达它们。
