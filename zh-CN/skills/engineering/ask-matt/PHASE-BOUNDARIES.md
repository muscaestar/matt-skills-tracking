# 阶段边界

**阶段（phase）**是会话中的一块工作——追问、实现、QA。这个定义故意模糊：当你觉得*“好，这件事我们做完了”*时，一个阶段就结束了。

**阶段边界（phase boundary）**是两个阶段之间的间隙，也是这个决策唯一应该发生的地方。阶段中途没有决策可做——要么继续，要么把剩余工作拆给子 agent。中途 compact 会让 agent 丢掉思路。

## 五个选项

| 选项 | 作用 |
| ------------ | --------------------------------------------------------------- |
| **Continue** | 留在当前会话，完全没有上下文切换。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写一份可移植的 markdown 文件，并可用它在任何地方启动会话。 |
| **Subagent** | 把任务发到它自己的上下文窗口，然后拿回一份报告。 |
| **`/compact`** | 压缩当前上下文，并用摘要启动一个新会话。 |

## 决策树

在边界处从上到下依次判断。第一个**是**获胜。

**1. 你能在这个会话中继续吗？** 有两种情况答案为是：下一阶段需要本阶段作为**一手来源**，或者你剩余的[智能区](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 150k token）足以容纳下一阶段。追问 → 实现是标准的“是”：实现需要的是逐字的推理过程，而不是它的摘要。Continue 不花成本也不丢东西，所以先排除它，再考虑其他选项。

**2. 当前上下文对接下来要做的事无关紧要吗？** 这个会话里的一切——探索、决策、死胡同——都可丢弃吗？如果是，就 **`/clear`**。这是棋盘上最便宜的一步：不花时间，还回整个窗口。`/clear` 也不是终点——旧会话仍可恢复。

这一步出错的代价是单向的。清掉一个*相关*的上下文，你就会丢掉你所做之事的**为什么**，事后读多少遍 diff 也找不回来。

**3. 你需要交接吗？** `/handoff` 用途很窄。只有以下情况才需要它：

- 换到**新 harness**（Claude → Codex），
- 换到**新目录**或仓库，
- 把工作交给**同事**，
- 或在**阶段中途**分叉一个支线任务，且不让手头工作脱轨。

这个清单就是全部条件。`/handoff` 换来的是**可移植性**——一份能带走、能流转的文件。如果没有东西需要流转，你就不需要它。

**4. 这个任务可以离开键盘（AFK）完成吗？** 它的范围是否紧到可以在你不在键盘前、无需掌舵的情况下运行？如果是，就把它交给**子 agent**，并让当前会话保持不动。自动化审查是标准场景：agent 读 diff 并回报，期间不需要你。

**5. 否则，`/compact`。** 上下文相关、harness 相同、目录相同，而你又需要留在环中——决策树通常会落到这里，而且经常落到这里。给它传一条指令（`/compact we're going to QA this area`），让摘要保留下一阶段需要的内容。

`/compact` 是**默认选择，而不是第一选择**。它位于树底，因为前面的四个问题都更便宜或更精确。人们一开始就选它时的失败模式是：一个新会话对摘要压平了的某个决策自信满满，却是错的。

## 一手来源与二手来源

除 **Continue** 之外的每一步，都会把**一手来源**变成**二手来源**——会话原原本本发生的过程，被它的一份摘要取代。这个权衡始终具有相同形态：

| 来源 | 信息 | 噪声 | 可操作空间 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一手（Continue） | 完整 | 多 | 小 |
| 二手（`/compact`、`/handoff`） | 有损 | 少 | 大 |

这就是问题 1 排在最前的原因。只有当留下的代价高于它节省的东西时，你才需要付出有损的代价。

## 这些是判断

这些问题不是客观的——每一个都带有个人判断，同一个边界在不同日子可能做出不同选择。价值在于**按顺序**提问，在边界处提问，而不是在工作中途。
